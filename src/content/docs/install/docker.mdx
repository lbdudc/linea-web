The `deploy/` folder of the [LINEA repository](https://github.com/lbdudc/linea) contains a Compose file that starts everything: MongoDB (as a replica set), the LINEA server, the web client and a Traefik proxy. It pulls the published images, `ghcr.io/lbdudc/linea-server` and `ghcr.io/lbdudc/linea-client` (amd64 and arm64), which already carry the official [plugins](/configure/plugins/) and the metamodels. Pin a version with `LINEA_VERSION=1.2.3` in `.env` (the default is `latest`).

```bash
git clone https://github.com/lbdudc/linea
cd linea/deploy
```

<FileTree>

- linea/
  - deploy/
    - docker-compose.yml
    - docker-compose.plugins.yml  optional services (flamapy)
    - .env.example  copy to `.env` for local use
    - .env.prod.example  copy to `.env.prod` for production
    - linea.config.example.yml
    - config/
      - linea.config.yml  mounted at `/config` in the container
    - config-gitlab/
      - linea.config.yml  GitLab as the only git host
  - apps/server/
    - .env.example  GitLab or GitHub OAuth, when you use them (put your values in `.env.local`)

</FileTree>

## The images

| Image | Carries |
|---|---|
| `ghcr.io/lbdudc/linea-server` | the API, the `local` git host, generation; the official plugins and the metamodels |
| `ghcr.io/lbdudc/linea-client` | the web interface, built with the plugins' client code |
| `ghcr.io/lbdudc/linea-flamapy` | the analysis service of the analytics plugin (`docker-compose.plugins.yml`) |
| `ghcr.io/lbdudc/linea-agents` | the agents' service of the agents plugin |

They are public and built for amd64 and arm64. Tags: the release version (`0.2.0`), `0.2` and `latest`.

## First start

<Steps>

1. **Create the Compose settings.** `JWT_SIGN_KEY` signs the sessions: set it to a long random string (`openssl rand -hex 32`).

   <Tabs>
   <TabItem label="Local trial">

   ```bash
   cp .env.example .env
   ```

   Edit `.env`: change `JWT_SIGN_KEY` and `LINEA_ADMIN_PASSWORD`. The defaults serve LINEA on [http://localhost:9000](http://localhost:9000) with the `local` git host.

   </TabItem>
   <TabItem label="Production">

   ```bash
   cp .env.prod.example .env.prod
   ```

   Set the key, the public address and the administrators:

   ```ini
   JWT_SIGN_KEY=<openssl rand -hex 32>
   PROXY_PORT=18009
   NODE_ENV=production
   REDIRECT_URI=https://linea.example.com
   PUBLIC_SERVER_URL=https://linea.example.com
   ADMIN_USERS=alice,bob
   ```

   </TabItem>
   </Tabs>

2. **Choose how people sign in.** With nothing configured LINEA uses the `local` host: set the first administrator in `deploy/.env`.

   ```ini
   ADMIN_USERS=admin
   LINEA_ADMIN_PASSWORD=choose-a-long-password
   ```

   For GitLab or GitHub follow [Connect GitLab](/configure/gitlab-oauth/) or [Connect GitHub](/configure/github-oauth/) instead.

3. **Start the stack.**

   <Tabs>
   <TabItem label="Local trial">

   ```bash
   docker compose up -d
   ```

   </TabItem>
   <TabItem label="Production">

   ```bash
   docker compose --env-file .env.prod up -d
   ```

   </TabItem>
   <TabItem label="With plugins">

   ```bash
   docker compose -f docker-compose.yml -f docker-compose.plugins.yml up -d
   ```

   Adds the flamapy analysis service used by the [analytics plugin](/configure/plugins/).

   </TabItem>
   </Tabs>

4. **Open the address** you set in `REDIRECT_URI` ([http://localhost:9000](http://localhost:9000) by default) and sign in.

</Steps>

## The services

| Container | Image | Role |
|---|---|---|
| `splalm-mongo` | `mongo:8.2` | Database, started as replica set `rs0`. A one-shot container initiates the set. |
| `splalm-server` | built from `apps/server` | API, engine, generation. Reads `server/.env` and the `environment:` block. |
| `splalm-client` | built from `apps/client` | The web client. |
| `splalm-proxy` | `traefik:v3.6` | Exposes `PROXY_PORT` and routes by labels. |
| `splalm-flamapy` | built from `plugins/analytics-plugin/service` | Only with `docker-compose.plugins.yml`. |

Two named volumes keep your data: `mongo-data` and `repos-data` (the repositories of the `local` host, mounted at `/data/repos`).

<Aside type="caution">
The server container mounts the Docker socket (`/var/run/docker.sock`) so the playground runner can start containers. Treat access to the LINEA server like access to the Docker host, and do not expose the server port directly: only the proxy.
</Aside>

## Changing configuration later

<Aside type="note" title="Environment changes need a recreate">
Docker reads `env_file` when a container is created. After editing `server/.env`, recreate the server so it picks the change up:

```bash
docker compose up -d --force-recreate server
```

A change to `linea.config.yml` needs only a restart, because the file is read at startup: `docker compose restart server`.
</Aside>

## Where the configuration file goes

`deploy/config/linea.config.yml` is mounted read-only at `/config`. To use another folder set `LINEA_CONFIG_DIR`; the GitLab-only example is a ready-made case:

```ini
# deploy/.env.prod
LINEA_CONFIG_DIR=./config-gitlab
```

See [linea.config.yml](/reference/linea-config-yml/) for the format.

## Updating

```bash
git pull
cd deploy
docker compose --env-file .env.prod up -d
```

MongoDB and the repositories live in volumes, so rebuilding keeps your data.


Building the images yourself (to run a change): check out [`linea-plugins`](https://github.com/lbdudc/linea-plugins) and [`linea-metamodels`](https://github.com/lbdudc/linea-metamodels) next to `linea`, and run `docker compose up -d --build`.
